## 1. Claude's Google Drive connector: on demand, never streaming

Anthropic's help article states Claude "only accesses your data when you
explicitly ask a question or request an action", that a Drive file added to a
chat is processed "when you send your message", and that Docs "sync directly
from Google Drive, so you're always working with the latest version" — a
fetch at read time. The side-pane live-editing mode "re-reads the current
content" before each change. There is no push or polling mechanism exposed.
Conclusion: the connector cannot watch a document as the user types; a
watcher must be built.

Constraints on Google's side:

| Fact | Source |
|---|---|
| Drive push notifications are empty POSTs; content must be fetched after; no latency target; `files` channels expire after 1 day; "editor file revisions can be merged" | Drive API push + change-overview docs |
| Docs API read quota 300 requests/min/user/project | Docs API usage limits |
| Apps Script has no `onEdit` for Docs (Sheets only) | community threads (anecdotal) |
| Typing-to-cloud sync delay reported 1–3 s; Sheets push cadence reported ~3 min | community threads (anecdotal, unmeasured) |
| Google Docs renders on canvas, so browser extensions cannot read text from the DOM | spell-checker developer note |

Design consequence: poll `documents.get` every 3–5 s and diff paragraphs; use
the connector (or Claude Docs comment-summoning) only for heavier periodic review.

## 2. Tiered model cascade: feasible, with three cautions

Pricing (Claude API, cached 2026-10-06): Haiku 5.5 $0.10 / $0.50 per MTok,
Fable 5.1 $10 / $50. Cautions from the cascade literature and the API
guidance: calibrate escalation thresholds from your own workload, not
intuition; prompt caches are model-scoped so a cascade forfeits cache reuse
across tiers; measure "one capable model at low effort" before committing to a
cascade; judge cost per completed audit, not per request. Haiku 5.5 has no
server-side refusal fallback.

Decision in this spike: deterministic code for numbers; Haiku for per-claim
verdicts via the SDK (not via headless Claude Code — process startup, harness
tokens, tool surface and billing all argue against it for a per-paragraph
loop); headless Claude Code with tools and Fable only on escalation.

## 4. Loki: what was code and what was a model call (read from source)

| Stage | LLM | Deterministic |
|---|---|---|
| Decompose | 1 call, JSON list, 3 seeded retries | NLTK sentence fallback |
| Restore spans | 1 call | verbatim `find()`, overlap clamping |
| Check-worthy | 1 batched call | parse, filter "Yes"; default all check-worthy |
| Query gen | 1 batched call/pass, ≤3 passes | claim is always query 1; cap 5 |
| Retrieval (Serper) | none | Serper API, top-3, optional 500-char page window; no ranking |
| Retrieval (base class) | none | spaCy chunking + MiniLM cross-encoder (ML, not LLM) |
| Verify | 1 call per claim×evidence | retries; IRRELEVANT placeholder; group by claim |
| Score | none | supports/(supports+refutes); mean over claims |

## 5. Pituitary: per command (read from README, runtime.md, workflows.md)

Deterministic core (SQLite index, tree-sitter AST edges, graph community
detection). Optional embedder: `check-compliance`, `search-specs`, near-miss
in `check-terminology`. Optional analysis LLM (bounded, shortlisted context,
recorded in output): `compare-specs`, `check-doc-drift` refinement,
`analyze-impact` severity, `canonicalize`, `check-compliance` re-adjudication.
Never: `check-terminology`, `fix`, `search-specs`, `status`, `explain-file`.
Specs are declared `spec.toml` bundles; docs are linked by configured sources.

## 6. Replacement decisions

- **Loki → PaperQA2 + a Haiku structured-output verdict prompt.** LettuceDetect
  was first chosen as a cheap tier and then dropped for the pilot: it is the
  one domain-sensitive component and the pilot runs on out-of-domain topics.
- **Pituitary → generated numbers + Vale + a small custom extractor.** Pituitary
  never reconciled numbers; its unique value (spec graph) is not what this
  needs. Keep it only for governance graphs, and as a beta you may fork.
