## Fixed inputs

- Base: the served index root (`data/thinclient_index`, E8 dv-v2 manifest).
  Delta root on LOCAL disk (`SFU_DELTA_ROOT=/var/tmp/delta_ingest`) — §3 M2.
- Queries: the 120 natural topics used by every serve-path eval
  (`BENCHMARK_METHODOLOGY.md`); `search_rrf`, `top_k=50`, serving flags,
  2 passes, host otherwise idle.
- Delta corpus: (a) **synthetic-from-base** — 50k docs sampled from the base
  meta with titles/abstracts fetched via the sidecar, re-ingested as
  "updates" with one appended sentence (measures the masks + score drift
  with known ground truth); (b) **real new works** — 200k OpenAlex works
  from the newest free snapshot partitions newer than 2026-06-16 that are
  absent from `meta.sqlite` (measures the real thing); profile `desktop_gpu`.
- Results files: `data/eval_results/delta_ingest_<M>_<date>.json`; scripts
  under `scripts/experiments/eval_delta_ingest_*.py` (to be written with the
  run, one per M).

## Promotion rule

The gate stays default-OFF until M1, M2, M3 and M4 pass on the real stack and
the numbers are recorded in `02_DESIGN.md` §3/§4 with results-file paths and
absolute dates. Failing M3 or M4 opens the named follow-ups (score
normalisation; in-place delta-shard loading) as their own pre-registrations.

## Order of work

1. M1 + M6 (cheap, no quality question). 2. M7 on one partition (decides
whether the snapshot adapter is viable at all on the free tier). 3. M2/M3 on
corpus (a). 4. M4/M5 with corpus (b). 5. M8 alongside 4.

## Explicitly out of scope for this spike

Learned semantic ids (`semantic_docid_ingest/`), the base fold-in rebuild
(needs a re-export path that no longer exists), livedocs bitsets (§4.3 of
the design — needed before snapshot-scale deletes, not before the bars
above), arXiv/Zotero/S2 adapters (mechanical), the result-cache stamp (R1),
dense-leg enqueue.

### Scope and order changes (decided 2026-09-29, before any run)

- **M7 is measured first**, ahead of M1+M6. Reason: the research passes
  (`04_IMMUTABILITY_RESEARCH.md` conclusion 2) made the content-hash churn
  filter the load-bearing assumption of the write-amplification argument
  (`02_DESIGN.md` §4 item 1); if it fails, the snapshot adapter's cost model
  changes before any serving bar matters.
- **Livedocs bitset is now IN scope** (it was listed as out of scope above).
  Reason: OpenAlex `deleted_ids` runs to tens of millions of rows, which the
  JSON mask list cannot hold (`02_DESIGN.md` §4 item 3), and the bitset also
  fixes S5. Bars were pre-registered in the harness header of
  `scripts/experiments/eval_delta_ingest_livedocs_bitset.py` (commit
  35b11c75, before the run; arm order revised before the run in af15c2e1).
- **M9 — twin-shard rebuild parity (new, pre-registered 2026-09-29 in commit
  aa0fc405 before any comparison ran).** Bar copied verbatim from the header
  of `scripts/experiments/eval_delta_ingest_twin_rebuild.py`:

  ```
  PRE-REGISTERED PARITY BAR (written 2026-09-29 before any comparison ran):
    query sets     : the 120 topics (data/sfu_eval_queries.json, "query" field,
                     the n120 set) + n=100 diverse queries
                     (data/eval_results/diverse_queries.json via
                     e6_forward_codec_proto.load_queries, first 100 distinct
                     paraphrases).
    encoding       : E8 harness conventions (scripts/seismic_testbed/e8_dvv2_gates.py):
                     encode_splade(q, "models/splade_onnx_fp16"), top-64 terms by
                     weight, all 64 passed to the engine.
    search params  : E8 recall-max params, identical on both shards:
                     seismic.MmapSeismicIndex, k=k'=200, query_cut=len(terms),
                     heap_factor=0.8, SFU_SEISMIC_PREFLOOR=2 in the environment.
    metric         : overlap@10 = |top10_rebuilt ∩ top10_served| / 10 per query
                     on doc-id strings (the E5 row permutation of the served
                     shard is therefore irrelevant).
    PASS iff       : mean overlap@10 >= 0.99 on EACH query set, the E8 per-shard
                     bar (served dv-v2 vs its f16 twin measured 0.993-0.997).
    Reported, not gated: min overlap@10, count of queries with identical top-10
                     (as a set and in order).
    A FAIL is recorded as a FAIL.
  ```
- **M10 — 9-shard pilot (pre-registered 2026-09-29 for a later run; NOT RUN).**
  Split one f16 twin by `blake2b % 16` (seed `sfu-seismic-plan01`) into two
  half-shards, build both, serve manifest = 7 served shards + 2 halves.
  Bars: mean overlap@10 of the 9-shard manifest vs the 8-shard manifest
  ≥ 0.99 on the 120 topics; warm parallel `search_rrf` p50 ≤ +10% vs the
  8-shard manifest. Sequential Σ recorded, no bar. Depends on M9 PASS. Did
  not run in the 2026-09-29 window (it needs M9's verdict and two further
  ~30 min shard builds, which did not fit; M9 then FAILED its bar, so the
pilot's premise is not met either).
